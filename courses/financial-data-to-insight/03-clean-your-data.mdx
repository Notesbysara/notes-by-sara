## Nine checks before you trust a file

<div className="nbs-sec"><p>You don't need special software. Each check below can be done in Excel or Google Sheets.</p> <div className="steps"> <div className="step"> <div className="step-head"><span className="n">1</span><h3>Duplicates</h3></div> <div className="def"><p>A <b>duplicate</b> is a row that repeats another row at the same grain, so the same thing is counted more than once.</p></div> <p>It usually happens when two files are combined, or the same export is pasted twice. Totals and counts go up, and nothing looks wrong.</p> <p className="eg"><b className="lab">Example</b> The copied row above. Same date, same store, same amount.</p> <p className="tip"><b className="lab">Tip</b> In Excel, Home › Conditional Formatting › Highlight Cells Rules › Duplicate Values shows repeats in a column, and Data › Remove Duplicates deletes rows that match on the columns you choose. Conditional formatting compares single cells, though, so a repeated amount or date isn't always a duplicate row. To check whole rows, add a helper column such as =COUNTIFS(A:A,A2,B:B,B2)&gt;1, which shows TRUE when the same date and store appear more than once. And check against the grain: if one row is one single sale, two identical rows can both be real.</p> </div> <div className="step"> <div className="step-head"><span className="n">2</span><h3>Missing values</h3></div> <div className="def"><p>A <b>missing value</b> is a cell with nothing recorded in it. It is not the same as zero.</p></div> <p>A blank can mean “nothing happened” or “we don't know”. Those lead to different answers, so find out which before you fill it in.</p> <div className="tw small-t"><table><tbody> <tr><th>Day</th><th style={{textAlign:"right"}}>Sales</th></tr> <tr><td>Monday</td><td className="r">10</td></tr><tr><td>Tuesday</td><td className="r">20</td></tr><tr className="flag"><td>Wednesday</td><td className="r">(blank)</td></tr> </tbody></table></div> <p className="eg"><b className="lab">Example</b> Excel's AVERAGE skips the blank and gives 15. If someone types 0 into the blank, the average becomes 10. Same data, different answer.</p> <p className="tip"><b className="lab">Tip</b> =COUNTBLANK(B2:B100) counts the empty cells in a range, so you know how many there are before you start.</p> </div> <div className="step"> <div className="step-head"><span className="n">3</span><h3>Formats</h3></div> <div className="def"><p>A <b>format problem</b> is a value stored in a form the spreadsheet can't use correctly, such as a number saved as text or a date saved as text.</p></div> <p>Text numbers often come from system exports. Excel usually shows them aligned to the left, sometimes with a small green triangle in the corner.</p> <div className="tw small-t"><table><tbody> <tr><th>Day</th><th style={{textAlign:"right"}}>Sales</th></tr> <tr><td>Mar 3</td><td className="r">1,164</td></tr><tr className="flag"><td>Mar 4</td><td style={{textAlign:"left"}}>975 (stored as text)</td></tr><tr><td>Mar 5</td><td className="r">985</td></tr> <tr className="total"><td>=SUM(…)</td><td className="r bad">2,149</td></tr> </tbody></table></div> <p className="eg"><b className="lab">Example</b> SUM skips text in a range, so this total is 2,149 instead of 3,124, and no error appears.</p> <p className="tip"><b className="lab">Tip</b> =ISNUMBER(B2) returns TRUE only for real numbers. =VALUE(B2) turns text into a number, and =TRIM(A2) removes extra spaces, though not the non-breaking spaces some exports contain.</p> </div> <div className="step"> <div className="step-head"><span className="n">4</span><h3>Inconsistent labels</h3></div> <div className="def"><p><b>Inconsistent labels</b> are different spellings or names used for the same category.</p></div> <p>“North”, “Nth” and “North ” (with a space at the end) look like one region to you, but a spreadsheet treats them as three. Your region totals split into pieces.</p> <p className="eg"><b className="lab">Example</b> A PivotTable by region shows North at $0.62m and “Nth” at $0.18m, instead of one North total of $0.80m.</p> <p className="tip"><b className="lab">Tip</b> Click the filter arrow on a column to see every distinct value in it (“North ” with a space can look identical to “North”, so =LEN(A2) helps spot it). Fix the variants with Find and Replace, and use Data › Data Validation with a list to stop new ones.</p> </div> <div className="step"> <div className="step-head"><span className="n">5</span><h3>Units and scale</h3></div> <div className="def"><p><b>Scale</b> is the multiplier a number is reported in, such as units, thousands or millions.</p></div> <p>Topic 2 showed how to spot the scale. Cleaning means converting everything to one scale before you combine files.</p> <p className="eg"><b className="lab">Example</b> One file shows sales as 2,310 in thousands, another as 2,310,000 in dollars. Multiply the first by 1,000 before putting them in one table.</p> <p className="tip"><b className="lab">Tip</b> Put the scale in the column heading, such as “Sales ($000)”, so nobody has to guess. If files are in different currencies, convert them to one currency and write down which exchange rate you used, for example the month's average rate.</p> </div> <div className="step"> <div className="step-head"><span className="n">6</span><h3>Signs</h3></div> <div className="def"><p>A <b>sign convention</b> is the rule for whether an amount is shown as positive or negative.</p></div> <p>Some systems show refunds and costs as negative numbers, others as positive numbers in a separate column. Mixing the two rules flips amounts the wrong way.</p> <p className="eg"><b className="lab">Example</b> A $340 refund should reduce sales. If it's added as +340 instead of −340, sales are overstated by $680, twice the refund.</p> <p className="tip"><b className="lab">Tip</b> Choose one rule, write it in your schema map, and convert every file to it.</p> </div> <div className="step"> <div className="step-head"><span className="n">7</span><h3>Totals that don't match</h3></div> <div className="def"><p><Term slug="reconciliation" name="Reconciliation" def="Reconciliation is the process of comparing two sets of records to check that they agree, and investigating and correcting any differences."><b>Reconciliation</b></Term> is comparing two sets of records to check that they agree, and investigating and correcting any differences.</p></div> <p>If the parts don't add up to the total, or two reports disagree, something is missing, repeated or in the wrong place.</p> <div className="tw small-t"><table><tbody> <tr><th>Region</th><th style={{textAlign:"right"}}>Sales ($m)</th></tr> <tr><td>North</td><td className="r">0.80</td></tr><tr><td>South</td><td className="r">0.62</td></tr><tr><td>East</td><td className="r">0.50</td></tr><tr><td>West</td><td className="r">0.39</td></tr> <tr className="total"><td>Sum of regions</td><td className="r">2.31</td></tr><tr><td>Total in the annual report</td><td className="r">2.31</td></tr><tr className="total"><td>Difference</td><td className="r">0.00 ✓</td></tr> </tbody></table></div> <p className="tip"><b className="lab">Tip</b> Add a check cell, =SUM(parts)-Total, and look for 0. On a <Term slug="balance-sheet" name="Balance Sheet" def="A balance sheet is a financial statement that shows what a business owns, what it owes and what belongs to its owners at a specific date.">balance sheet</Term>, assets must equal liabilities plus equity, so the same check works there.</p> </div> <div className="step"> <div className="step-head"><span className="n">8</span><h3>Outliers</h3></div> <div className="def"><p><Term slug="outlier" name="Outlier" def="An outlier is a data point that is very different from most of the other values in a data set.">An <b>outlier</b></Term> is a data point that is very different from most of the other values in a data set. Any that fall in different months are worth checking: make sure each is counted in the month the sale actually happened.</p> </div> </div></div>

## Fix, flag or remove

<div className="nbs-sec"><p>Finding a problem is half the job. The other half is deciding what to do about it, and that decision should never be a guess.</p> <div className="tw"><table><tbody><tr><th>Do this</th><th>When</th><th>Example</th></tr><tr><td><b>Fix</b> it</td><td>You can confirm the right value from a source</td><td>The till receipt shows $985, so 9,850 was a typing error</td></tr><tr><td><b>Flag</b> it</td><td>You can't confirm it yet, and it might matter</td><td>A blank day of sales: keep it blank, mark it, and ask</td></tr><tr><td><b>Remove</b> it</td><td>You're sure it shouldn't be counted for your question</td><td>An exact duplicate row, or a test transaction</td></tr></tbody></table></div> <p>Whichever you choose, write it in the change log. A flagged problem also goes in your message to whoever uses the numbers, so they know what's still open.</p> <p className="tip"><b className="lab">Tip</b> When you're unsure, flag rather than fix or remove. A flag can be cleared later. A wrong fix hides the problem.</p></div>

## Three habits that keep cleaning safe

<div className="nbs-sec"><div className="steps"> <div className="step"> <div className="step-head"><span className="n">A</span><h3>Keep the raw data untouched</h3></div> <p>Copy the original into a tab called Raw and never edit it. Do your cleaning on a copy, so you can always go back.</p> </div> <div className="step"> <div className="step-head"><span className="n">B</span><h3>Make every change repeatable</h3></div> <p>Use formulas or recorded steps rather than typing over cells by hand. In Excel, Power Query (Data › Get Data) records each cleaning step, so next month you can refresh the file and repeat the same cleaning in minutes.</p> </div> <div className="step"> <div className="step-head"><span className="n">C</span><h3>Keep a change log</h3></div> <div className="def"><p>A <b>change log</b> is a list of every change you made to a dataset, with the reason for each. It's part of the data's <Term slug="audit-trail" name="Audit Trail" def="An audit trail is a step-by-step record showing how a transaction or figure was created, changed and approved, linking final reported numbers back to their source documents.">audit trail</Term>.</p></div><p>One line per change: what you changed, why, and how many rows it touched. If anyone questions a number, you can show exactly how you got it. Also note the number of rows and the total before and after cleaning (these are called control totals), so you can show nothing was lost or added by accident.</p> </div> </div></div>

## What this looks like at work

<div className="nbs-sec work"><p>Most finance work starts with someone else's file. For example:</p> <ul> <li>Another team sends month-end numbers that you need to report on.</li> <li>You export data from a company system, and some columns come out as text.</li> <li>You combine two spreadsheets that were set up in different ways.</li> </ul> <p>Each time, run the nine checks first. It's much easier to fix a problem before your numbers go into a report than after.</p> <p>Two more things professionals do. First, prioritize: chase down the errors big enough to change a decision before polishing small ones. Second, if the same problem keeps coming back, tell whoever owns the data, so it gets fixed at the source and not just in your copy.</p></div>

## How you'd say it to your manager

<div className="nbs-sec"><p>Tell people what you found and changed, so they can trust the numbers that follow.</p> <div className="msg"> <p className="eyebrow">Example message</p> <p className="body">Hi Maya, I cleaned the March sales file before analyzing it. I removed one duplicate row, fixed a number Excel was reading as text, tidied one region label, and corrected one typing error (9,850 should be 985, per the till receipt). Store S02's sales for March 5 are missing, so the March total is incomplete until we get that day. Every change is listed in the Log tab.</p> </div> <p className="small">Notice it says what changed, why, and what's still open.</p></div>

<div className="nbs-sec"><div className="remember"> <p className="eyebrow">Remember</p> <ul> <li>Run the nine checks before you trust a file: duplicates, missing values, formats, labels, units and scale, signs, totals, outliers and dates in the right period.</li> <li>A blank is not a zero. Find out what it means.</li> <li>Flag outliers and check them. Don't delete them by reflex.</li> <li>Never edit the raw data. Clean a copy, and log every change.</li> </ul> </div></div>
